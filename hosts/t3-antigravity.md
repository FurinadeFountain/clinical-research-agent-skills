## 宿主执行与集成（T3 Code / Antigravity 补充示例）

- **比例化执行与子代理路由（T3 Code 强约束）**：常规单线任务由主代理直接完成，复用已核证据，仅在结果变化、报错或高风险疑点时扩大检验；需检视本地文件时附精确 `file://` 链接。仅当复杂开放任务可拆为独立问题且并行确能提效时委派子代理（上限 7 个，禁递归委派）：**在 T3 Code 环境下严禁调用 Antigravity 原生 `invoke_subagent` / `define_subagent`**（在 T3 UI 不可见、写文件与命令权限确认易超时且主线程结单后无法自动唤醒），本规则显式覆盖“同提供方用原生工具”默认提示。无论同模型还是跨提供方，**所有子代理与并行任务统一使用 T3 Code 的 `delegate_task`**（线程首次先调 `orchestrator_capabilities` 实时核查可用实例与模型，并行改码设 `isolation="worktree"`）。
- **跨家族能力互补与提供方对齐**：严格保持提供方与模型家族对齐——默认经 `codex` 调用 OpenAI GPT 旗舰、经 `antigravity` 调用 Google Gemini 4 非 Flash 旗舰（若另配其他第一方提供方则走对应官方通道），**避免经单一通道混挂其他厂商模型**（如不经 `antigravity` 调用非 Google 模型）。主代理（Gemini 4）专司统筹、破框发散、中英行文与视觉制图；涉及复杂生信/数值代码根因排障、统计防泄漏复核或密集一手文献/药理核查时，按需派只读 `codex` `sol` 系列（如 `gpt-6.2-sol`）；涉及重大立意批判、反方质疑或砍题裁决时，按需派只读 `codex` `astra` 系列（如 `gpt-6.2-astra`），具体型号以 `orchestrator_capabilities` 实查为准。
- **独立学术审阅入口**：仅对已完稿且涉实质科学判断的正式手稿、大修核心章节、基金标书或正式报告（或明确请求）调用 `academic-reviewer`；普通讨论、早期构思、配置维护与纯措辞润色不触发。T3 Code 下优先经 `delegate_task` 发起异构跨家族互审；具体模型白名单、推理深度、“1 轮全审＋条件触发至多 1 轮局部复核”封顶与三级分流漏斗统一由 `academic-reviewer` 单点维护。
- **MCP 直连与首轮回退**：外部连接器（如 `mcp_notion_*`）若在新线程首轮尚未握手就绪，优先使用预设命令行桥接工具兜底，不排查配置目录或改用浏览器抓网页。
- **后台命令与媒体读取防雷**：T3 Code 下 `run_command` 超 10 秒转入后台后，**严禁以“正在等待后台任务、稍候回报”结束回合**（ACP 回合结束即结单并丢弃后续异步唤醒，`t3_background_wait` 亦仅限部分宿主）。常规验证优先采用 10 秒内同步轻量检查（`py_compile`、单测、按页局部渲染）；若命令已转后台，先完成其他独立步骤再用 `manage_task(status)` 回收，未结束则直接交付已落盘文件路径与日志路径并明示需手动复查。**严禁在写入/渲染后台任务确认退出前用 `read_file` 读取目标图像或 PDF**（截断图片解码失败会将残缺字节写入历史导致后续回合持续报错）；批量渲染或绘图脚本须先输出至临时目录、校验完整后再 `os.replace()` 原子发布。
