# 网页模型咨询

仅在用户要求外部模型意见，或核查现有材料与一手来源后仍有会改变核心决策的开放研究分歧时调用。先用一句话明确外部咨询要解决的分歧；能靠代码、数据或权威资料直接裁定的问题不外询。配置维护、常规检索、局部修改及用户要求不用其他模型时跳过。默认咨询一个模型的一次完整答复，必要时针对一个未解关键分歧追问；没有新证据或判断增量即停止，不追求模型一致。只有新的独立分歧确需第二视角时才加问，三模型对比仅在用户要求时展开。

## 问题与背景整理

先通读当前材料，锁定决策目标、既有证据、真实约束与核心分歧（如方法可行先例、竞争设计判别力、替代方案权衡）。提问时提供充分上下文，要求答复明确给出推荐理由、适用边界、反对视角及待查的一手依据线索。

多模型对比同一选择题时，向各方提供完全一致的事实前提与研究约束（保持任务本身设定的理想或实际条件边界，避免私自缩减研究范围），各自独立首答后再针对关键分歧展开交叉追问。

## 浏览器操作与模型选型

按当前宿主可用的浏览器工具规范（如宿主共享预览浏览器、已配置的 `ego-browser` 或内置网页侧栏）使用真实网页对话并优先复用相关标签页与会话，完成页面观察、模型切换、提问与完整结果读取。默认按用户要求启用最大思考深度选型：

| 网页端 | 必须核对并选中的模型 / 模式 |
| --- | --- |
| Gemini | **4 Argon**：Chat 模式设为 High（或显示 Argon High）；Task 模式直接选用 Argon |
| Grok | **Expert** 模式 |
| ChatGPT | **Pro** 模型 |

综合复杂问题优先咨询 **ChatGPT Pro**；当存在影响核心判断的技术盲区、强反对论证需求或首轮答复存在重要遗漏时，再按疑点加问 **Grok Expert** 或 **Gemini 4 Argon High**（可根据后续实测表现灵活调整）。

发送前在界面核实当前实际选中的模型与模式名称，遵守用户后续指定优先级。若遇指定选项不可用、额度耗尽或登录受限，如实汇报具体阻碍及对咨询覆盖的影响，保持原状态而不自行降档切换旧版本模型。严格控制外部传输内容至讨论必要背景，遵守本次任务敏感数据边界与授权范围。

## 深入追问、防卡死与一手查证

等待生成完成后展开并读取全部相关内容及引用线索；如外部网页深度思考耗时过长、超时或断连，**严禁无限轮询或空手结束回合**——如实向用户报告当前会话状态、已读到的部分内容及页面标签状态，必要时交由用户在浏览器中直接查看，不把主线程挂死在等待中。默认 1 轮答复，仅针对遗漏约束或关键分歧在原会话内追问至多 1 轮。

将影响最终决策的关键分歧改写为可检验命题，回溯原始论文、官方文档或实测记录逐一核实（仅将模型引文作为检索线索）。划分事实勘误、研究取舍与尚需实验/数据解决的不确定性；待核心疑点获得足够证据支持或明确实验判定边界后即结束讨论。

汇总时直接给出自己的整合裁决（采纳、修正或舍弃的建议及理由），在原任务授权范围内直接落入现有文稿、方案或图表并交付结果，最终向用户交代实际咨询的模型、改变的关键判断以及仍待验证的问题。
